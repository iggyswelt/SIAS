## Cron-Jobs Architektur-Wissen
- `cron/jobs.json` ist die Quelle der Wahrheit für Cron-Konfiguration
- `systemEvent` kind + `sessionTarget: "main"` → SystemEvent wird an Agent-Hauptsession geschickt
- Agent reagiert auf systemEvent und führt das Script aus
- stdout des Scripts landet im Chat wenn nicht umgeleitet → daher `exec 1>/dev/null 2>/dev/null` ODER alles ins Log
- `cron/runs/*.jsonl` = Lauf-Logs der Cron-Jobs, sind nur Historie
- Cron-Jobs mit `enabled: false` werden NICHT im `openclaw cron list` angezeigt, Scheduler sollte sie ignorieren
